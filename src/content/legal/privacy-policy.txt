- Capturing screenshots of the active application window
- Extracting limited textual signals from specific regions
- Combining this with activity metadata to improve predictions
OCR processing is designed to be privacy-aware, selective, and context-limited.

When the OCR feature is enabled, the application may capture screenshots of the active user interface during active usage, used to extract contextual signals and improve classification of work activity.
OCR is performed locally on the user's device:
- Raw image data is processed on-device
- Text extraction occurs without sending full screenshots externally (unless explicitly configured otherwise)
Text is extracted only from specific screen regions:
- Left region — workspace/project context
- Top region — active screen context
- Bottom region — user intent signals
The central content area is not processed by default, reducing exposure to sensitive information.
The system captures screenshots and performs OCR only when:
- The user is actively using their device
- Application or window context changes
- Interaction (e.g., typing or navigation) is detected
The system does not capture or process data when:
- The user is idle
- Applications are minimized or inactive
- No meaningful screen change occurs

Screenshot Retention
- Screenshots are stored for up to 90 days by default
- Retention duration may be configured by the organization based on internal policies
- After the retention period, screenshots are automatically deleted or anonymized
OCR Data Retention
- OCR-derived data is retained only as structured tokens and metadata
- Raw textual reconstruction is not retained beyond operational necessity
We implement multiple safeguards to minimize data exposure:
- Only selected screen regions are processed; low-confidence or irrelevant text is discarded: Data Minimization
- Short, duplicate, or non-meaningful tokens are removed; confidence thresholds limit noisy data usage: Filtering Mechanisms
- Broader OCR processing may occur only when necessary and is automatically reverted: Controlled Escalation
- Detection and filtering mechanisms reduce capture of personally identifiable information; extracted content is used strictly for prediction purposes: PII Guardrails
We protect collected data through:
- Encryption in transit and at rest
- Secure, industry-standard storage systems
Access to screenshot and OCR-derived data is governed by Role-Based Access Control (RBAC), ensuring:
- Only authorized personnel can access such data
- Access is granted based on role and business need
- Access activities may be logged and monitored
Given the nature of internet communications, Ralvie cannot guarantee absolute security of information during transmission or storage.
